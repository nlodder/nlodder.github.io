# Working in this repo

## How I want you to work

- Work in large batched edits, not incremental ones. Rewrite a file rather than making eight small edits to it.
- Don't narrate progress or summarize what you did unless I ask. No status reports mid-task.
- Keep responses short. Answer the question, don't add a report.
- Ask clarifying questions in one batch, up front, before writing code — not as they occur to you.

## Project

Personal portfolio at nlodder.github.io. Static site served by GitHub Pages.

**No build step, no framework, no dependencies, no ES modules.** Plain files:

- `index.html` — home: bio, list of pages, social links
- `projects.html` — projects page shell (empty `#project-list` + media viewer markup)
- `data/projects.js` — **all project content**, one array; add/remove/reorder blocks here
- `js/projects.js` — renders the array into project blocks, scrollers, expand/collapse
- `js/media-viewer.js` — the fullscreen glass media viewer
- `style.css` — all styling, shared by both pages
- `assets/images/<project>/`, `assets/videos/<project>/` — media, one folder per project

Font Awesome is the only external resource (CDN link in `<head>`).

## Conventions

- **Colors live in `:root` in `style.css`.** Never hardcode a color elsewhere — add a variable.
- **Vanilla JS only**, plain `<script>` tags (order matters in `projects.html`: data, viewer, projects).
- **Mobile-first CSS.** Base rules target mobile; `@media (min-width: 768px)` holds desktop overrides.
- Project blocks are generated by JS from `data/projects.js` — don't hand-write them in HTML. Figure captions are auto-numbered and scroller dots are generated, so they can't drift from the media list.
- New pages: add an HTML file, link `style.css`, and add an `<a>` to `.page-list` in `index.html`, and put a `.breadcrumb` (home / pagename) at the top of the new page.
- GitHub Pages is case-sensitive: asset paths must match filename case exactly.

## Don't

- Don't change the wording of any visible copy unless I explicitly ask. Project descriptions are mine.
- Don't add a build step, package.json, or framework.
- Don't reformat files wholesale — it makes the diff unreviewable.
